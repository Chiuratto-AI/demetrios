ARCHITECTURE

Julia Backend Flow:
Demetrios PBPK Model (Stanza) → Parser → TypeChecker → HLIR → Julia Codegen

Type Mapping:
- i32 → Int32
- i64 → Int64
- f64 → Float64
- bool → Bool
- unit → Nothing
- Custom types → @kwdef struct

Function Generation:
1. Parameter struct (using @kwdef for default values)
2. ODE function (f(du, u, p, t) format for DifferentialEquations.jl)
3. Solve wrapper (uses Tsit5 solver by default)
4. Main script (demonstrates usage)

DifferentialEquations.jl Integration:
- Uses ODEProblem for problem definition
- Uses Tsit5 (Runge-Kutta 5th order) solver
- Supports custom solvers via tspan parameter
- Returns SciML-compatible solution object

TECHNICAL NOTES

DifferentialEquations.jl Integration:
The generated Julia code uses the standard SciML interface:
- Problem definition: ODEProblem(f!, u0, tspan, p)
- Solver call: solve(prob, alg, kwargs...)
- Solution access: sol.t (time), sol[i, j] (values)

Performance Expectations:
- Julia compilation: One-time overhead
- Julia execution: Typically faster than interpreter
- LLVM backend: Probably faster than Julia for simple models
- Trade-off: Julia has better ecosystem for analysis
