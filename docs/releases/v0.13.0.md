# Demetrios v0.13.0 Release Notes

**Release Date:** Day 19 of Bootstrap Phase  
**Focus:** Debugging, Profiling & Diagnostics Infrastructure

## Overview

Version 0.13.0 introduces comprehensive debugging, profiling, and diagnostic infrastructure for the Demetrios language. This release provides professional-grade tools for development, including DWARF debug information generation, GDB/LLDB integration, profiling frameworks, structured tracing, and a rich error diagnostic system.

## New Features

### Part A: Debug Information Generation

#### DWARF Debug Info Builder (`compiler/src/codegen/debug/mod.rs`)

- Full DWARF v5 debug information generation
- LEB128 (Little Endian Base 128) encoding for compact representation
- Support for:
  - Compilation unit headers
  - Line number information (DW_AT_decl_line, DW_AT_decl_column)
  - Type information (base types, structures, functions)
  - Variable locations and scopes
  - D-specific extensions (effects, linear types)

```rust
let mut builder = DebugInfoBuilder::new(
    PathBuf::from("main.d"),
    PathBuf::from("/src"),
);

// Add types
builder.add_type("int", 4, DwarfType::Base(BaseType::Signed));
builder.add_type("MyStruct", 16, DwarfType::Structure(fields));

// Add functions with effect annotations
builder.add_function("process_data", 0x1000, 0x1200, return_type, &effects);

// Generate DWARF sections
let debug_info = builder.finalize();
```

#### Source Maps (`compiler/src/codegen/debug/source_map.rs`)

- Source Map v3 specification implementation
- VLQ (Variable-Length Quantity) encoding for compact mappings
- Features:
  - Source embedding support
  - Symbol name mapping
  - D-specific extensions for effects and type info
  - Bidirectional lookup (generated → original, original → generated)

```rust
let mut builder = SourceMapBuilder::new();
builder.add_source_with_content(path, source);
builder.add_mapping(gen_line, gen_col, &source_path, orig_line, orig_col, Some("fn_name"));
builder.add_effects("process", vec!["IO", "Alloc"]);
let source_map = builder.build("output.map");
```

### Part B: Debugger Integration

#### GDB Pretty Printers (`compiler/debug/d_gdb.py`)

Python-based GDB integration providing:
- Pretty printing for D types:
  - `DString` - String with length display
  - `DVec<T>` - Vector with element preview
  - `DOption<T>` - Some/None display
  - `DResult<T,E>` - Ok/Err display
  - `DBox<T>` - Pointer with target display
  - `DLinear<T>` - Linear type with ownership state
  - `DEffect` - Effect handler visualization
- Custom GDB commands:
  - `d-effects` - Show active effect handlers
  - `d-linear` - Show linear type states
  - `d-backtrace` - Enhanced backtrace with effects

#### LLDB Support (`compiler/debug/d_lldb.py`)

Python-based LLDB integration with:
- Type summaries matching GDB functionality
- Synthetic children for container types
- Custom commands for D-specific debugging
- Effect and linear type inspection

### Part C: Profiling Infrastructure

#### CPU Profiler (`stdlib/profile/mod.d`)

Sampling-based CPU profiler:
- Configurable sample rate (default: 1000 Hz)
- Stack trace collection with symbol resolution
- Flame graph generation (SVG output)
- Profile report generation (JSON, text formats)
- Hotspot identification

```d
let profiler = CpuProfiler::new(SampleRate::Hz(1000));
profiler.start();
// ... code to profile ...
let report = profiler.stop();
report.write_flamegraph("profile.svg");
```

#### Memory Profiler (`stdlib/profile/mod.d`)

Allocation tracking profiler:
- Per-allocation tracking with stack traces
- Peak memory usage detection
- Allocation site aggregation
- Leak detection
- Memory timeline visualization

```d
let profiler = MemoryProfiler::new();
profiler.start();
// ... code to profile ...
let report = profiler.stop();
println!("Peak usage: {} bytes", report.peak_bytes);
println!("Total allocations: {}", report.total_allocations);
```

#### Async Profiler (`stdlib/profile/async_profile.d`)

Task-aware profiler for async code:
- Task lifecycle tracking (spawn, poll, complete)
- Poll duration measurement
- Task dependency visualization
- Chrome trace format export
- Task timeline generation

```d
let profiler = AsyncProfiler::new();
profiler.start();
// ... async code ...
let report = profiler.stop();
report.export_chrome_trace("async_trace.json");
```

### Part D: Tracing Framework

#### Structured Tracing (`stdlib/trace/mod.d`)

Comprehensive tracing system:
- Hierarchical spans with timing
- Structured events with key-value fields
- Multiple log levels (Trace, Debug, Info, Warn, Error)
- Pluggable subscribers:
  - `FmtSubscriber` - Human-readable console output
  - `JsonSubscriber` - Machine-readable JSON lines
  - `OtelExporter` - OpenTelemetry protocol export
- Thread-safe global dispatcher

```d
let _span = span!("request_handler", 
    method = "GET",
    path = "/api/users"
);

event!(Level::Info, "Processing request");

// Nested span
{
    let _db_span = span!("database_query");
    event!(Level::Debug, query = sql, "Executing query");
}

event!(Level::Info, status = 200, "Request complete");
```

#### Metrics System

Built-in metrics primitives:
- `Counter` - Monotonically increasing values
- `Gauge` - Point-in-time measurements  
- `Histogram` - Value distribution tracking

### Part E: Diagnostic System

#### Rich Error Diagnostics (`compiler/src/diagnostic/mod.rs`)

Professional error reporting:
- Source code highlighting with spans
- Multiple labels per diagnostic
- Help and note annotations
- Suggestion system with applicability levels

```rust
let diagnostic = DiagnosticBuilder::error("T0001", "Type mismatch")
    .with_span(expr_span)
    .with_label(expr_span, "expected `int`, found `bool`")
    .with_label(fn_span, "function expects `int` return type")
    .with_help("consider converting the value with `as int`")
    .build();
```

#### Error Code Registry (`compiler/src/diagnostic/codes.rs`)

Comprehensive error code system:
- ~40 error codes across categories:
  - `L0xxx` - Lexer errors
  - `P0xxx` - Parser errors  
  - `T0xxx` - Type errors
  - `F0xxx` - Effect errors
  - `O0xxx` - Ownership errors
  - `R0xxx` - Refinement type errors
  - `U0xxx` - Unit of measure errors
  - `G0xxx` - Code generation errors
  - `I0xxx` - Internal compiler errors
- Full documentation for each code
- Searchable error index

#### Diagnostic Emitters (`compiler/src/diagnostic/emitter.rs`)

Multiple output formats:
- `HumanEmitter` - Colored terminal output with source context
- `JsonEmitter` - Machine-readable JSON output
- `SarifEmitter` - SARIF format for IDE integration

#### Suggestion System (`compiler/src/diagnostic/suggestion.rs`)

Code fix suggestions:
- Applicability levels (machine-applicable, has placeholders, unspecified)
- Multi-suggestion support
- Common patterns library:
  - Add semicolon
  - Make variable mutable
  - Add type annotation
  - Add effect annotation
  - Fix import path

### Part F: CLI Commands

New compiler commands:

```bash
# CPU/Memory/Async profiling
dc profile <file.d> --profile-type cpu --duration 10 --flamegraph output.svg
dc profile <file.d> --profile-type memory
dc profile <file.d> --profile-type async --output trace.json

# Debugging with pretty printers
dc debug <file.d> --debugger gdb --pretty
dc debug <file.d> --debugger lldb --pretty

# Error code documentation
dc explain T0001
dc explain O0003

# Error index browsing
dc error-index
dc error-index --category type
dc error-index --category effect

# Debug info generation
dc debug-info <file.d> --output debug.dwarf

# Source map generation
dc source-map <file.d> --output output.map
```
