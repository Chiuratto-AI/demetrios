# Demetrios v0.30.0: The Epistemic Paradigm Shift

**Release Date**: December 2025

## Overview

Version 0.30.0 represents a fundamental paradigm shift in how programming languages handle knowledge and uncertainty. This release introduces the complete **Knowledge[τ, ε, δ, Φ] type system**, where every value carries its epistemic history.

Traditional languages treat types as syntactic constraints. Demetrios treats types as **ontological assertions about reality**.

## Key Features

### 1. Four-Layer Ontology Architecture

A comprehensive hierarchy scaling from ~850 to ~15 million terms:

| Layer | Terms | Source | Purpose |
|-------|-------|--------|---------|
| L1 Primitive | ~850 | Built-in | Language primitives |
| L2 Foundation | ~8,000 | PATO, UO, IAO, Schema.org, FHIR | Cross-domain concepts |
| L3 Domain | ~500,000 | ChEBI, GO, DOID, etc. | Domain-specific terms |
| L4 Federated | ~15M | BioPortal, OLS | On-demand resolution |

### 2. L2 Foundation Ontologies (`src/ontology/foundation/`)

Bootstrap ontologies providing essential vocabulary:

- **PATO** (Phenotypic Quality Ontology): ~2,500 terms for qualities and attributes
- **UO** (Units of Measurement): ~1,000 unit definitions with SI base unit tracking
- **IAO** (Information Artifact Ontology): ~300 terms for data and documents
- **Schema.org**: ~2,850 types for web-structured data
- **FHIR R5**: ~1,150 healthcare resources

Each term is augmented with initial epistemic status during load.

### 3. L3 Domain Ontologies (`src/ontology/domain/`)

Lazy-loaded SQLite-backed access to domain ontologies:

- **ChEBI**: Chemical entities
- **GO**: Gene Ontology
- **DOID**: Disease Ontology
- **HP**: Human Phenotype
- **MONDO**: Merged disease ontology
- **UBERON**: Anatomy
- **CL**: Cell types
- **NCBITaxon**: Taxonomic classification
- **PR**: Protein ontology
- **SO**: Sequence ontology
- **ENVO**: Environment ontology
- **OBI**: Biomedical investigations

Uses Semantic-SQL schema for efficient querying.

### 4. L4 Federated Resolution (`src/ontology/federated.rs`)

Enhanced federated resolver with epistemic awareness:

```rust
pub struct FederatedTerm {
    pub id: String,
    pub label: String,
    pub definition: Option<String>,
    pub synonyms: Vec<String>,
    pub parents: Vec<String>,
    pub source: FederatedSource,
    pub epistemic: EpistemicStatus,  // NEW
}
```

Computes initial confidence based on:
- Source reliability (OLS4: 0.85, BioPortal: 0.80)
- Definition presence
- Obsolescence status

### 5. Dependent Ontological Types (`src/check/epistemic.rs`)

Types that encode epistemic requirements:

```demetrios
type Aspirin = Knowledge[
    ChEBI:15365,
    ε ≥ 0.95,              // Minimum confidence
    δ ⊆ SmallMolecule,     // Domain constraint
    Φ: ChEBI → verified    // Provenance requirement
]
```

Features:
- Confidence threshold constraints
- Evidence requirements (Publication, Experimental, Computational)
- Temporal validity constraints
- Provenance requirements (FromSource, Verified, MaxDepth, HumanReviewed)

### 6. Epistemic Heterogeneity Resolution (`src/epistemic/heterogeneity.rs`)

When combining knowledge from different sources with different confidence levels:

```rust
pub enum ResolutionStrategy {
    Prioritized,        // Trust highest-priority source
    Bayesian,          // Log-odds Bayesian combination
    AGM,               // AGM belief revision
    Consensus { threshold: u8 },
    Conservative,      // Take minimum confidence
    Optimistic,        // Take maximum confidence
    WeightedAverage,   // Weight by confidence
}
```

Includes conflict detection and resolution suggestions.

## API Examples

### Creating Epistemic Status

```rust
use demetrios::epistemic::*;

// Axiomatic (certain, non-revisable)
let axiom = EpistemicStatus::axiomatic();

// From measurement
let measurement = EpistemicStatus::from_measurement(0.95, "mass_spectrometer");

// Derived from dependencies
let derived = EpistemicStatus::derived(&[&dep1, &dep2], "calculation");
```

### Checking Epistemic Constraints

```rust
use demetrios::check::epistemic::*;

let checker = EpistemicChecker::new();

// Create ontological type with requirements
let ty = checker.type_with_confidence("CHEBI:15365", 0.9)?;

// Check if value satisfies type
let result = checker.check_constraint(&value_status, &ty);
```

### Resolving Heterogeneity

```rust
use demetrios::epistemic::heterogeneity::*;

let resolver = HeterogeneityResolver::with_strategy(ResolutionStrategy::Bayesian);

let result = resolver.resolve(&[source1, source2, source3])?;
println!("Combined confidence: {}", result.combined.confidence.value());
```

### Integrity Checking

```rust
use demetrios::diagnostic::epistemic::*;

let mut checker = EpistemicIntegrityChecker::new();
checker.check_status(&status, "variable_name");

if checker.has_errors() {
    for diag in checker.diagnostics() {
        println!("{}: {}", diag.code.code(), diag.message);
    }
}
```

## Migration Guide

Existing code continues to work unchanged. To adopt epistemic types:

1. Import epistemic module: `use demetrios::epistemic::*`
2. Annotate critical values with confidence requirements
3. Enable epistemic warnings in compiler config
4. Review IDE hints for low-confidence paths
