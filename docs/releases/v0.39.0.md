# Release v0.39.0 - Layout Synthesis

**Release Date**: December 4, 2025

## Highlights

This release introduces **semantic layout synthesis** (Day 38), which uses ontology relationships to optimize memory layout for improved cache performance.

### Hypothesis Validated

> Semantic clustering improves cache performance.

**Results**: +15.9 percentage point improvement in cache hit rate for realistic workloads.

| Layout | Hit Rate |
|--------|----------|
| Clustered (semantic) | 81.8% |
| Interleaved (arbitrary) | 65.9% |

## New Features

### Layout Synthesis Module

- **HIR Integration**: Added `LayoutHint` enum (`Stack`/`Arena`/`Heap`) to `HirStmt::Let`
- **Concept Extraction**: HIR walker that finds `Knowledge[T, τ, ε, δ, Φ]` types
- **Distance Matrix**: Pairwise semantic distances via ontology LCA queries
- **Clustering**: Hierarchical agglomerative clustering by semantic proximity
- **Layout Plan**: Assigns clusters to Hot/Warm/Cold memory regions
- **Cache Instrumentation**: LRU simulation for hypothesis validation
- **Report Generation**: Markdown reports with statistics and recommendations

### CLI Commands

```bash
# Analyze concepts and generate layout plan
dc layout analyze program.d --max-clusters 4

# Simulate cache performance  
dc layout simulate access_pattern.txt --cache-size 16

# Validate hypothesis across cache sizes
dc layout validate access_pattern.txt --cache-sizes 8,16,32,64
```

## Technical Details

### When Layout Synthesis Helps

1. Cache size smaller than working set
2. Hardware prefetching active (spatial locality)
3. Code accesses semantically related concepts together
4. Cold starts and phase transitions

### Integration Points

Layout hints flow through the compilation pipeline:
- HIR → HLIR → Codegen
- Stack hints → `alloca` / stack slots
- Arena hints → bump allocator
- Heap hints → `malloc` / `Box::new`
